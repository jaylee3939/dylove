# 도연아, 사랑해 ♡

A personal, fully local 3D story adventure built with React, TypeScript, Vite, React Three Fiber, drei, Three.js, and Zustand. All player-facing text is Korean. No backend, paid API, personal voice recording, or third-party photograph is required.

## Private visual story editor

See [the Korean editor guide](EDITOR.ko.md). Run `npm run editor` locally to edit all six stages, common UI text, character names, captions, and the letter without TypeScript. Draft saves are separate from game progress. Export a complete JSON and send it to Codex for an intentional content update. The editor is excluded from production; existing Vercel hosting and URLs remain unchanged.

## 11.11 standalone special episode

Open `/special/1111` for the independent six-chapter special: prologue, Busan and taste quizzes, 11-heart touch game, four date choices, and the full letter/couple ending. Main game stays at `/`; saves are isolated. See [the Korean special guide](SPECIAL-1111.ko.md). Optional photos may be added in the dedicated event data; the existing local editor is preserved and its special-event panel is a later integration.

## Run

Requires Node.js 22.18+ (tested with Node 24) and npm.

```sh
npm ci
npm run dev
```

Open the address printed by Vite in a local browser. For a phone on the same network, use the development machine's LAN address and port 5173. Cloud onboarding does not provide a public preview URL automatically.

```sh
npm run build
npm run preview
npm test
```

`npm run build` runs strict TypeScript checks and produces `dist/`. `npm test` checks story structure, choice reactions, the exact love letter, and photo configuration. `npm run test:browser` also checks touch joystick input. `node tests/browser.mjs` runs the actual browser journey against a running dev or production preview server on port 5173; it uses the npm-distributed Chromium binary for Linux cloud environments. Browser screenshots are written to `/tmp`.

## Play

- Desktop: WASD / arrows to walk; E to interact. Touch or mouse for menus.
- Phone: drag the lower-left joystick; tap the lower-right interaction button.
- Approach a pink marker. Complete the story interaction, close the memory photo, then use **하트 받기** at the same marker.
- Collect the five main memory hearts in order. The fifth opens the photo slideshow and original love letter.
- The optional hotel door and sixth location unlock after five hearts. The scene contains affectionate, non-explicit interactions only.
- The travel menu replays unlocked stages. After the ending, the album revisits collected memories.
- Progress is stored on this browser/device in LocalStorage (`doyeon-love-v1`). Restarting requires confirmation. Clearing browser storage removes progress. Private browsing may not retain it.
- Music is an original procedural sine-wave melody generated by Web Audio after a player gesture; footsteps and interaction chimes are synthesized. The sound button mutes everything.

## Replace the photos

Use the **추억 사진 관리** section of the [private visual editor](EDITOR.ko.md): upload multiple JPG/PNG/WebP photos, reorder/replace/delete, edit each title/caption, and export one ZIP with every story edit and optimized image. Send that ZIP to Codex for a reviewed update to the existing Vercel game. Photos stay in browser IndexedDB until you export/publish; the editor makes no upload requests. Legacy JSON drafts remain supported. The steps below are an optional developer workflow.

No personal photos were supplied; the game intentionally shows empty Korean Polaroid frames. Add JPEG/WebP images to `public/memories/`, then edit **only** `src/data/memories.ts`:

```ts
photos: ["/memories/tokyo-01.jpg", "/memories/tokyo-02.webp"];
```

Multiple photos per memory are supported. Failed image loads fall back to an empty frame. Photos in a deployed static site are public to anyone who obtains their URL; use only pictures you want to share.

## Customize

| File                           | Content                                                                                    |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| `src/content/gameContent.ts`   | Validated published copy merged onto unchanged game structure                              |
| `src/content/published.json`   | Intentionally published text document, initially null                                      |
| `src/data/story.ts`            | Stage names, destinations, dialogue, choices, actions, heart messages, exact ending letter |
| `src/data/memories.ts`         | Album captions and photo paths                                                             |
| `src/data/characters.ts`       | Shared editable character palette                                                          |
| `src/characters/Character.tsx` | Reusable hierarchical procedural character rig and editable palette                        |
| `src/scenes/Environment.tsx`   | Six miniature 3D sets and reusable props                                                   |
| `src/scenes/GameWorld.tsx`     | Camera, walking boundaries, proximity markers, player/NPC staging                          |
| `src/systems/store.ts`         | Persistent progress and transient movement input                                           |
| `src/systems/audio.ts`         | Original audio synthesis                                                                   |
| `src/styles/game.css`          | Mobile safe areas, Korean UI, letter transitions                                           |

Characters are real geometry inspired by the supplied sheet: Doyeon's long brown hair, half-up bun, bangs, cream cardigan, dark dress and shoes; Jaeyeong's beige cap, resting sunglasses, white shirt, dark shorts and white shoes. Character components accept `kind`, `moving`, `action`, and `rings`, allowing replacement with GLTF implementations later. Actions use procedural poses rather than imported skeletal animation clips. Rings appear during selection and persist on both characters afterward. Hugging, kissing, patting, waving, sitting, walking, and affectionate hand poses are stylized approximations; they are not motion-captured animation.

For new locations, extend the stage/memory data and provide its environment artwork. The current main story deliberately has five hearts and one optional bonus; changing this structure also requires updating its progress rules/UI. Interaction props are decorative geometry; walking is bounded to accessible floor space rather than a physics simulation. Portrait rendering caps DPR at 1.5, uses shared low-detail geometry, instanced street paving, a baked contact pass, and one shadow-casting light. Actual iPhone Safari and device performance should be checked before gifting; desktop mobile emulation is not a physical-device test.

## Deploy to Vercel

1. Push this project to your GitHub repository.
2. In Vercel, choose **Add New → Project**, import the repository, and select the **Vite** framework.
3. Build command: `npm run build`. Output directory: `dist`. No environment variables are needed.
4. Deploy and open the resulting HTTPS URL on the phone. Test music after tapping start, joystick movement, the ending, and save/continue.
5. Share the Vercel HTTPS URL with Doyeon.

`vercel.json` includes the build settings and immutable hashed-asset caching. No deployment or public URL is created by running the local build.
